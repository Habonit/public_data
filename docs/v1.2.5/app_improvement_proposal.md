## 1. 개요

본 문서는 대구 공공데이터 시각화 앱 v1.2.4의 현재 상태(AS-IS)와 v1.2.5에서 목표하는 개선 상태(TO-BE)를 비교 분석한다.

v1.2.5의 핵심 목표:
1. **🔴 버그 재수정**: test_data 헤더 인식 문제 (v1.2.4에서 수정 시도했으나 **미해결**)
2. **➕ 신규 기능**: AI 챗봇 보고서 생성 기능
3. **🔧 구조 개선**: material 폴더 넘버링 규칙 표준화

> ⚠️ **중요**: test_data 헤더 인식 문제는 v1.2.4에서 수정을 시도했으나 해결되지 않았습니다. v1.2.5에서 근본 원인을 재분석하여 완전히 해결합니다.

## 2. 기능별 AS-IS / TO-BE 비교

### 2.1 테스트 데이터 업로드 기능 (⚠️ v1.2.4 미해결 이슈 재수정)

| 구분 | AS-IS (v1.2.4) | TO-BE (v1.2.5) |
|:-----|:---------------|:---------------|
| **헤더 인식** | ❌ test.csv 업로드 시 첫 행이 데이터로 인식됨 (v1.2.4 수정 실패) | ✅ 첫 행이 정상적으로 컬럼명으로 인식됨 |
| **컬럼명** | `column1`, `column2`, `column3`, ... ("column"{숫자인덱스}) | `ID`, `사고일시`, `요일`, `기상상태`, `시군구`, `도로형태`, `노면상태`, `사고유형` |
| **데이터 행** | 헤더 행이 첫 번째 데이터로 포함됨 | 실제 데이터만 포함됨 |

#### 2.1.1 v1.2.4 수정 실패 분석

**v1.2.4에서 시도한 수정:**
```python
# v1.2.4에서 적용한 수정 (효과 없음)
df = pd.read_csv(
    io.BytesIO(content),
    encoding=enc,
    header=0  # 첫 행을 헤더로 명시적 지정
)
```

**v1.2.4 수정이 실패한 원인 분석:**
| 가능한 원인 | 설명 | 검증 방법 |
|:-----------|:-----|:---------|
| BOM 처리 미흡 | UTF-8-BOM 인코딩 시 첫 바이트가 헤더 인식에 영향 | `encoding='utf-8-sig'` 추가 |
| 업로드 파일 타입 | Streamlit UploadedFile 객체의 seek 위치 문제 | `uploaded_file.seek(0)` 호출 |
| 다중 인코딩 루프 | 인코딩 루프에서 이전 시도의 부작용 | BytesIO 객체 재생성 확인 |
| train.csv와 test.csv 인코딩 차이 | 파일별 인코딩 불일치 | 파일 인코딩 직접 확인 |

#### 2.1.2 v1.2.5 해결 방안

```python
# TO-BE (v1.2.5)
def read_uploaded_csv(uploaded_file: BinaryIO) -> pd.DataFrame:
    content = uploaded_file.read()

    # UTF-8-BOM 우선 처리
    encodings = ['utf-8-sig', 'utf-8', 'cp949', 'euc-kr']

    for enc in encodings:
        try:
            df = pd.read_csv(
                io.BytesIO(content),
                encoding=enc,
                header=0,
                skipinitialspace=True  # 공백 제거
            )
            # 헤더 검증: 숫자로만 구성된 컬럼명이면 재시도
            if all(str(col).isdigit() for col in df.columns):
                continue
            return df
        except UnicodeDecodeError:
            continue

    raise ValueError("지원되지 않는 파일 인코딩입니다.")
```

## 3. 코드 품질 개선

### 3.1 test_data 헤더 인식 버그 (🔴 v1.2.4 미해결)

| 위치 | AS-IS (v1.2.4) | TO-BE (v1.2.5) | 심각도 |
|:-----|:---------------|:---------------|:-------|
| `utils/loader.py:read_uploaded_csv()` | 헤더 인식 로직 불완전 | 인코딩 우선순위 + 헤더 검증 로직 추가 | 🔴 Error |

#### 3.1.1 코드 수정 상세

```python
# AS-IS (v1.2.4) - 수정했으나 여전히 문제 발생
def read_uploaded_csv(uploaded_file: BinaryIO) -> pd.DataFrame:
    content = uploaded_file.read()
    for enc in encodings:
        try:
            df = pd.read_csv(io.BytesIO(content), encoding=enc, header=0)
            return df
        except UnicodeDecodeError:
            continue

# TO-BE (v1.2.5) - 완전한 수정
def read_uploaded_csv(uploaded_file: BinaryIO) -> pd.DataFrame:
    content = uploaded_file.read()

    # 1. BOM 처리를 위해 utf-8-sig 우선
    encodings = ['utf-8-sig', 'utf-8', 'cp949', 'euc-kr']

    for enc in encodings:
        try:
            df = pd.read_csv(
                io.BytesIO(content),
                encoding=enc,
                header=0,
                skipinitialspace=True
            )

            # 2. 헤더 검증: 모든 컬럼이 숫자면 헤더 인식 실패로 판단
            if all(str(col).isdigit() for col in df.columns):
                # 첫 행을 헤더로 재설정 시도
                df.columns = df.iloc[0]
                df = df[1:].reset_index(drop=True)

            return df
        except UnicodeDecodeError:
            continue

    raise ValueError("지원되지 않는 파일 인코딩입니다.")
```
